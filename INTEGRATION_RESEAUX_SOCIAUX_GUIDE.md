Principaux\n\n```\n┌─────────────────────────────────────────────────────────────┐\n│         SocialMediaAggregatorService (Centralisé)          │\n│  - Combine YouTube et Facebook                             │\n│  - Récupère les statistiques globales                       │\n│  - Fusionne les contenus                                   │\n└─────────────────────────────────────────────────────────────┘\n         ↓                                      ↓\n┌──────────────────────────┐      ┌──────────────────────────┐\n│ YouTubeIntegrationService│      │FacebookIntegrationService│\n│ - Récupère vidéos        │      │ - Récupère publications  │\n│ - Stats chaîne           │      │ - Stats page             │\n│ - 'youtube' | 'facebook'\n├─ action: 'view' | 'like' | 'share' | 'comment'\n├─ timestamp: DateTime\n└─ isSyncedToServer: bool\n\nEngagementStats (Hive)\n├─ contentId: String\n├─ viewCount: int (API)\n├─ ↓\nHubReseauxPage._loadData()\n    ↓\nSocialMediaAggregatorService.getRecentContent()\n    ↓\nYouTubeIntegrationService.getChannelVideos()\nFacebookIntegrationService.getPagePosts()\n    ↓\nAffichage ↓\nSocialInteractionTrackerService.trackInteraction()\n    ↓\nEnregistrement dans Hive (SocialInteraction)\n    ↓\nMise à jour EngagementStats\nMise à jour ActiveUser\n    ↓\nPrêt pour synchronisation YouTube/Facebook APIs\n    ↓\nMarkInteractionAsSynced()\n    ↓\nClearSyncedInteractions()\n```\n\n---\n\n## Implémentation\n\n### 1. ## 10. Sécurité des API Keys et Données Utilisateur

La sécurité est primordiale lors de l'intégration de services tiers et de la gestion des données utilisateur. Ce guide fournit des recommandations pour protéger vos API Keys et les informations sensibles.

### 10.1. Protection des API Keys

*   **Ne jamais exposer les API Keys directement dans le code client** : Les API Keys doivent être stockées de manière sécurisée et accessibles via des variables d'environnement ou un service de gestion de secrets. Pour les applications Flutter, l'utilisation de `flutter_dotenv` ou de `build_config` est recommandée pour charger les clés au moment de la compilation sans les inclure dans le code source versionné [4].
*   **Utiliser des restrictions d'API Key** : Limitez l'utilisation de vos API Keys aux services et adresses IP spécifiques qui en ont besoin. Pour YouTube Data API, restreignez la clé aux applications Android et iOS et à l'API YouTube Data v3 uniquement.
*   **Rotation régulière des clés** : Changez vos API Keys périodiquement pour minimiser les risques en cas de compromission.

### 10.2. Protection des Données Utilisateur

*   **Minimiser la collecte de données** : Ne collectez que les données strictement nécessaires au fonctionnement de l'application.
*   **Chiffrement des données sensibles** : Utilisez `flutter_secure_storage` pour stocker localement les tokens d'accès ou toute autre information sensible de manière chiffrée [5].
*   **Conformité RGPD/GDPR** : Assurez-vous que la collecte et le traitement des données utilisateur sont conformes aux réglementations en vigueur (par exemple, consentement explicite, droit à l'oubli).
*   **Communication sécurisée** : Toutes les communications avec les APIs externes et votre backend doivent se faire via HTTPS.

## 11. Intégration avec l'Espace Ministres

L'intégration des réseaux sociaux peut enrichir l'Espace Ministres en fournissant des données d'engagement et des contenus pertinents directement aux ministres.

### 11.1. Contenus Ciblés

Les ministres peuvent recevoir des directives incluant des liens vers des vidéos YouTube spécifiques ou des publications Facebook pertinentes pour leur ministère, facilitant ainsi la diffusion d'informations et de messages pastoraux.

### 11.2. Suivi de l'Engagement Ministériel

Les statistiques d'engagement (vues, likes) générées par les ministres via le Hub Réseaux peuvent être agrégées et présentées dans le Dashboard Ministre, offrant une vue sur leur participation active à la diffusion des contenus numériques de l'Église.

### 11.3. Partage de Contenus

Les ministres peuvent être encouragés à partager des contenus spécifiques depuis l'application vers leurs propres réseaux sociaux, amplifiant ainsi la portée des messages de l'Église, tout en assurant que ces partages sont trackés et comptabilisés.

## 12. Procédures de Dépannage Avancées

Cette section étend les procédures de dépannage pour des problèmes plus complexes.

### 12.1. Problèmes de Quota API

*   **Symptôme** : Les appels API échouent avec des erreurs de type `403 Quota Exceeded`.
*   **Solution** : Vérifiez votre utilisation de quota dans la Google Cloud Console (pour YouTube) ou le tableau de bord des développeurs Facebook. Augmentez le quota si nécessaire, ou optimisez vos appels API en utilisant la mise en cache.

### 12.2. Problèmes de Permissions d'Accès (Facebook)

*   **Symptôme** : Impossible de récupérer certaines données de la page Facebook ou d'effectuer des actions (ex: poster).
*   **Solution** : Vérifiez les permissions accordées à votre application Facebook dans le tableau de bord des développeurs. Assurez-vous que l'application a les permissions nécessaires (`pages_read_engagement`, `pages_manage_posts`, etc.) et qu'elles ont été approuvées par Facebook si l'application est en mode 
live. Pour les pages, assurez-vous que l'application est liée à la page via le Business Manager.

### 12.3. Problèmes de Synchronisation des Interactions Locales

*   **Symptôme** : Les interactions enregistrées localement ne sont pas envoyées au serveur backend ou ne sont pas reflétées sur les plateformes sociales.
*   **Solution** :
    1.  **Vérifier la connectivité réseau** : Assurez-vous que l'appareil a une connexion internet stable.
    2.  **Vérifier les logs du service de tracking** : Activez un niveau de log détaillé pour `SocialInteractionTrackerService` pour voir si les tentatives d'envoi échouent.
    3.  **Examiner la base de données Hive** : Utilisez un outil de débogage pour inspecter le contenu de la base de données Hive et vérifier le statut `isSyncedToServer` des interactions.
    4.  **Vérifier le backend** : Assurez-vous que le service backend est opérationnel et qu'il peut recevoir et traiter les données d'interactions.
    5.  **Gestion des erreurs de l'API backend** : Implémentez une logique de nouvelle tentative (retry logic) avec un backoff exponentiel pour les envois qui échouent temporairement.

### 12.4. Problèmes de Performance

*   **Symptôme** : L'application est lente lors du chargement des contenus sociaux ou des statistiques.
*   **Solution** :
    1.  **Mise en cache** : Implémentez un mécanisme de mise en cache pour les données des réseaux sociaux afin de réduire le nombre d'appels API et la fréquence de rafraîchissement.
    2.  **Pagination** : Utilisez la pagination pour charger les contenus par blocs plutôt que de tout charger en une seule fois.
    3.  **Optimisation des requêtes API** : Ne demandez que les champs nécessaires via les APIs pour réduire la taille des réponses.
    4.  **Chargement asynchrone** : Assurez-vous que toutes les opérations réseau et de base de données sont effectuées de manière asynchrone pour ne pas bloquer l'interface utilisateur.
